# GPU: 64 storage-buffer descriptors implemented (2026-08-14)

## Change (MoltenVK fork, branch moltenvk-macos)
- MVKPhysicalDevice::getMaxStorageBufferDescriptors(): 64 when Tier-2 argument
  buffers are active, else the 31 direct Metal buffer slots
- maxPerStageDescriptorStorageBuffers = getMaxStorageBufferDescriptors()
  (maxDescriptorSetStorageBuffers/Dynamic derive x5 = 320)
- Uniform buffers stay at 31 (D3D12 rung only needs storage >= 64)
- isTier2MetalArgumentBuffers() made const (reads only)

## Verification (mvkprobe against rebuilt dylib e80aae20)
  maxPerStageDescriptorStorageBuffers: 64   (was 31)
  maxPerStageDescriptorUniformBuffers : 31   (unchanged)
  maxPerStageDescriptorStorageImages  : 256  (already >= 64)

## Full-stack regression (evidence GPU-64uav-run1.txt)
Device creation at 11_0 OK; SM 6.5; max feature level still 11_0
(11_1 rung additionally requires OutputMergerLogicOp - the logic-op logicOp item).

## Documented limitations
- Push-descriptor layouts remain direct-binding (31 storage buffers) - the MVK
  push path (mvkPushDescriptorSet) is CPU-buffer-based and asserts
  argBufMode()==Off. vkd3d/D3D12 does not use Vulkan push descriptors, so the
  D3D12 route is unaffected; a Vulkan app using push layouts with >31 storage
  buffers would still be capped. Follow-up item: arg-buffer push descriptors.
- Variable-count storage-buffer layouts remain 31-capped (direct path).
