2. **Pipeline state capture** (MVKGraphicsPipeline): walks the pNext of the
   rasterization state for VkPipelineRasterizationConservativeStateCreateInfoEXT;
   stores the active flag + extra overestimation + the position attribute's
   vertex buffer layout (attribute location 0 = POSITION0, the D3D12/vkd3d
   convention).
3. **Shader-stage emulation injection** (MVKShaderModule.mm):
   - VERTEX: fetches the position attribute buffer (bound by the encoder at a
     reserved slot), converts to framebuffer pixels, expands each vertex
     outward along its own angle bisector by (2r + margin)/sin(theta/2) with a
     clip-boundary clamp, passes the ORIGINAL triangle as flat varyings, and
     outputs the expanded position (with a component swap compensating the
     Metal rasterizer's x/y-swapped viewport mapping observed on this stack).
   - FRAGMENT: D3D12 tier-1 post-snap test - round the flat vertices to the
     nearest pixel corner, test the pixel center against the snapped
     triangle's edge functions, discard uncovered fragments.
   - Encoder (MVKCommandEncoder::setCRConstants) binds the viewport + position
     layout constants and the app's position vertex buffer at draw time for CR
     pipelines.
4. **Rasterizer mapping discovery**: on this stack the Metal rasterizer maps
   the clip position with an x/y-swapped viewport transform (x_fb derived from
   the clip y, y_fb from the clip x). The injection emits the swapped
   position so the final rasterization lands at the correct coordinates. This
   is verified for the vertex positions (the expanded vertex renders at the
   expected pixel).

## CR EXECUTION: PIXEL-EXACT (12/12 seeds)

The vk-cr-probe is now pixel-exact in the MVK path: over=0 under=0 across
seeds 1..12 (16 random triangles each, 64x64, CPU post-snap reference).

Two fixes unlocked exactness (found via a pure-Metal reproduction of the
exact injected shader - scripts/probes/metal-cr-injected-probe.mm):

1. **SPIRV-Cross y-invert cancellation**: the injected position must be
   `float4(expNDC.x, -expNDC.y, z, w)` so the emitted
   `out.gl_Position.y = -(out.gl_Position.y)` line cancels to the identity.
   The earlier "x/y-swap" hypothesis was a misdiagnosis of the invert-induced
   mirror.
2. **Exact NDC round trip**: the injected pix2NDC y must NOT add +1
   (`1 - pix.y/h*2`, no `+1`), otherwise the rasterizer maps the expanded
   pixel back with a one-pixel y shift and edge pixels are lost.
